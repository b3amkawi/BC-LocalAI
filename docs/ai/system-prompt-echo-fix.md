# System prompt fix: answers that repeat the request, and answers that copy the previous short answer

AI-008 follow-up · 21 ต.ค. 2026 · Ollama 0.40.5 · qwen3:4b · scripts: `scripts/eval-chat-prompt.py`
พบจากการลองใช้หน้าแชต (FE-003 + BE-007) จริง

## อาการ (ผ่านหน้าเว็บ)
- "ขอโค้ดเปิดปิดไฟ arduino" ตอบกลับเป็นข้อความเดิมของผู้ใช้ ไม่มีโค้ด
- หลังถามเลขสั้น ๆ สองข้อ คำขอถัดไปได้ "5" หรือ "9"
- "เอาผลลัพธ์เมื่อกี้บวก 4" ตอบ 7 แทน 9 (หลังเปลี่ยน prompt แต่ยังไม่แก้ line break)
- "คำถามที่แล้วคืออะไร" ตอบเป็นคำตอบหรือคำถามข้อแรก

## สาเหตุที่วัดได้
1. **system prompt สั่งให้ตอบ "briefly" ร่วมกับบังคับ JSON `{answer}`** โมเดล 4B จึงทวนประโยคสั้น ๆ แบบ "ขอ ..." ลงในช่อง `answer` แม้ไม่มีประวัติ (2 จาก 20 คำขอ) และเมื่อมีประวัติคำตอบสั้นสองข้อ คำตอบเสียเพิ่มเป็น 16 จาก 20 (ตอบ "5" หรือทวนคำถาม)
2. **prompt ที่ Backend ส่งบน Windows ใช้ CRLF (`Environment.NewLine`)** ส่วนการทดสอบแบบ LF ให้คำตอบต่างกัน: ติดตามเลขได้ 9 เมื่อ LF แต่ 7 เมื่อ CRLF (system prompt เดียวกัน ประวัติเดียวกัน) prompt ไม่ควรขึ้นกับระบบปฏิบัติการ

## ที่แก้ (Backend)
- `OllamaGenerateRequest.SystemPrompt`: เพิ่มกฎ "ตอบตัวคำขอ ห้ามทวนหรือสรุปข้อความผู้ใช้ คำขอสั้นอย่าง 'ขอโค้ด ...' หมายถึงให้โค้ดนั้น" และตัวอย่างสามชุด (สูตรอาหาร, โค้ด, วิธีทำความสะอาด)
- `ConversationPrompt.Compose`: ใช้ `\n` เสมอแทน `Environment.NewLine`

## ผลวัด (20 คำขอสั้น × 3 ประวัติ = 60 ต่อแบบ; "เสีย" = ทวนคำขอ, สั้นกว่า 10 ตัวอักษร หรือเป็นตัวเลขล้วน)
| system prompt | ไม่มีประวัติ | ประวัติ 2 ตา | ประวัติ 3 ตา |
| --- | ---: | ---: | ---: |
| เดิม ("briefly" อย่างเดียว) | 2/20 | **16/20** | — |
| + กฎ anti-echo | 0/20 | 2/20 | 1/20 |
| **+ กฎ + ตัวอย่าง (ใช้จริง)** | **0/20** | **0/20** | **0/20** |
ติดตามเลข (a บวก b แล้ว "เอาผลลัพธ์เมื่อกี้บวก c") 8 ชุด: ทุกแบบถูก 8/8 ด้วย LF
ทดสอบผ่านหน้าเว็บจริง (เบราว์เซอร์ + MySQL ทดสอบแยก + Ollama จริง): 2+3 → "2 บวก 3 เท่ากับ 5", ติดตาม +4 → "5 บวก 4 เท่ากับ 9", ขอโค้ด arduino → ได้โค้ด `digitalWrite(...)`, ขอสูตรต้มยำกุ้งและอีเมลลาป่วย → ตอบเนื้อหา, จำชื่อและสีที่ชอบได้

## ที่ลองแล้วไม่ใช้
เทมเพลตประวัติแบบมีเลขลำดับ ("[1] User asked: ...", บอกว่ารอบไหนล่าสุด) ทำให้ "คำถามที่แล้วคืออะไร" ถูกขึ้น (2/5 → 4/5) แต่ทำให้ทวนคำขอเพิ่มเป็น **11 จาก 20** จึงยกเลิก แบบอื่น (หมายเหตุท้ายประวัติ, Q1/A1) ไม่ดีขึ้นพอ

## ข้อจำกัดที่ยังเหลือ
- คำถามเกี่ยวกับบทสนทนาเอง ("คำถามที่แล้วคืออะไร", "ข้อที่สองคืออะไร") ยังไม่น่าเชื่อถือ (ถูกประมาณ 2 ใน 5) เป็นข้อจำกัดของโมเดล 4B กับ prompt เดียว การส่งประวัติแบบ `/api/chat messages` ถูก 2 ใน 3 ในการทดสอบเล็กยังไม่พอจะเปลี่ยนสัญญา
- ตัวอย่างทดสอบเล็ก (20 คำขอ) และเป็นภาษาไทยเป็นหลัก; คุณภาพเนื้อหาของโมเดล 4B ยังจำกัด (เช่นสูตรอาหารไม่ครบ) ตัวอย่างใน prompt เพิ่มโทเคนราว 150 ต่อคำขอ (อยู่ในส่วนเผื่อ 100 + ที่เหลือของงบ 2,900)
- เปลี่ยน system prompt กระทบ baseline ของ benchmark เล็กน้อย (prompt ยาวขึ้น) สคริปต์ benchmark ยังใช้ system prompt เดิมจึงเทียบ AI-004/AI-006 ได้
