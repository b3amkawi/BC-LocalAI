# QA-002 Defect List (D4)

ผลทดสอบอยู่ใน [qa-002-results.md](qa-002-results.md) และ [qa-002-results-table.md](qa-002-results-table.md) หลักฐานดิบอยู่ใน [qa-002-evidence.json](qa-002-evidence.json)
จาก 256 กรณี รันกรณีละ 2 รอบ (512 การรัน) ผ่าน 249 กรณี **ไม่ผ่าน 5 กรณี** และมี 2 ข้อสังเกตที่ไม่มีเกณฑ์ผ่าน/ไม่ผ่าน

**ไม่พบข้อบกพร่องที่ทำให้เข้าถึงโดยไม่ได้รับสิทธิ์** ไม่พบการข้ามการยืนยันตัวตน, การอ่านข้อมูลผู้อื่น (IDOR), CSRF ที่ผ่าน, session ที่ไม่ถูกเพิกถอน, หรือคำขอที่ไม่ได้ล็อกอินแล้วเรียกถึง Ollama
ข้อบกพร่องที่พบเป็นการป้องกันชั้นเสริม (header, log, ช่วงเวลาตอบสนอง) ความรุนแรงสูงสุดคือปานกลาง ตามกติกา Issue ข้อบกพร่องด้านความปลอดภัยทุกข้อต้องแก้และทดสอบซ้ำ หรือ Leader ยอมรับความเสี่ยงเป็นลายลักษณ์อักษร ข้อที่เสนอให้ยอมรับความเสี่ยงระบุไว้ในคอลัมน์ข้อเสนอ

ความรุนแรง: **สูง** = เข้าถึงข้อมูล/ฟังก์ชันโดยไม่ได้รับสิทธิ์ · **ปานกลาง** = ทำให้การป้องกันหลักอ่อนลงหรือสิ้นเปลืองทรัพยากรโดยไม่ได้รับสิทธิ์ · **ต่ำ** = ขาดการป้องกันชั้นเสริม ไม่มีเส้นทางโจมตีที่พบ · **ข้อมูล** = ข้อสังเกต

| QA2-N04 | **คำขอที่ไม่มี Origin และ Sec-Fetch-Site (สคริปต์/เครื่องมือ) ไม่ถูกตัดโดย guard** ตามการออกแบบ (CSRF ต้องมีเบราว์เซอร์) การป้องกันของ endpoint นี้ = cookie SameSite=Lax + guard ข้ามเว็บ + ต้องเป็น JSON (`415` กับ `text/plain`/ฟอร์ม) ไม่ใช้ antiforgery token กับ `/api/chat*` และ `/api/conversations*` จึงไม่ต้องแนบ token (ทดสอบแล้วทั้งแนบและไม่แนบ) ตรวจเบราว์เซอร์จริงกับ FE-003 ยังไม่ได้ (ดู "สิ่งที่ไม่ได้ทดสอบ") | `QA2-C-allow-no-browser-headers`, `QA2-C-simple-text-plain`, `QA2-C-stream-fetch-*` |
| QA2-N05 | ไม่มี endpoint `/health` (404 ทุก role) | `QA2-M-health-*` |
